# 05 ปรับหน้าตาหน้า login และหลังบ้าน + เช็กมาร์กบน QR ที่มีวีดีโอแล้ว

## เป้าหมาย

ผู้ใช้ทดสอบบน production แล้วพบว่าทุกอย่างใช้งานได้ แต่ขอให้หน้า login และหน้าหลังบ้านดูสวยและเป็นมืออาชีพขึ้นก่อนส่งให้ลูกค้า (ลูกค้าองค์กร LOXLEY ไม่ใช่สาย tech ใช้มือถือเป็นหลัก) และ**ชุดไหนมีวีดีโอแล้ว ให้มีไอคอนเช็ก/ติ๊กถูกที่ QR ของชุดนั้น** ขอบเขตเป็นเรื่องหน้าตาเท่านั้น ห้ามเปลี่ยนพฤติกรรมหรือ API

## แนวทางดีไซน์

- **โทนเดียวกับหน้าดูวีดีโอ:** พื้นดำ ตัวอักษรครีม สีทอง `#d4af37` เป็นสีหลัก ดูหรูแบบเรียบ ไม่ฉูดฉาด
  - กำหนด token เป็น CSS variables เช่น bg `#0b0b0c`, surface `#151517`, surface-2 `#1d1d20`, border `#2a2a2e`, text `#f3eee2`, muted `#a39e93`, gold `#d4af37`, gold-hover `#e6c45c`, success `#3fbf7f`, danger `#e5484d`
  - คอนทราสต์ผ่านเกณฑ์ WCAG AA
- **ฟอนต์ไทย:** self-host **Sarabun** (OFL) เป็น woff2 ใน `public/assets/fonts/` น้ำหนัก 400 และ 600 subset ไทย + ละติน ใช้ `font-display: swap` และโหลดเฉพาะหน้า admin/login ห้ามโหลดจาก Google หรือ CDN
  - ได้ไฟล์มาจาก devDependency `@fontsource/sarabun` แล้ว copy ไฟล์ที่ใช้จริงเข้า repo พร้อมไฟล์ license
  - หน้าดูวีดีโอไม่ต้องโหลดฟอนต์นี้ ให้เบาเหมือนเดิม
- **ไอคอน:** SVG inline เขียนเอง ห้ามใช้ icon CDN หรือ icon font
- **มือถือก่อน:** ไม่ต้องเลื่อนแนวนอนที่ 360px ปุ่มแตะง่าย (≥ 44px)
- มี focus ring ที่เห็นชัด รองรับ `prefers-reduced-motion`

## Acceptance criteria

- [ ] AC1 **หน้า login** (`/admin/login`):
  - การ์ดกึ่งกลางจอ กว้างไม่เกิน ~400px
  - ส่วนหัวมีโลโก้/ไอคอนสีทอง "ระบบจัดการวีดีโอ" และบรรทัดรอง "ปฏิทิน QR วีดีโอ" (ห้ามใช้โลโก้จริงของ LOXLEY)
  - ช่อง username / รหัสผ่านมี label ชัดเจน และปุ่มแสดง/ซ่อนรหัสผ่าน (มี `aria-label`)
  - ปุ่มเข้าสู่ระบบสีทองเต็มความกว้าง ระหว่างส่งแสดงสถานะ "กำลังเข้าสู่ระบบ..." และกดซ้ำไม่ได้
  - ข้อความ error / ล็อก / busy / ฟอร์มใหญ่เกินแสดงเป็นกล่องแจ้งเตือนที่มีไอคอน (`role="alert"`)
  - ข้อความทุกอย่างเหมือนเดิม
- [ ] AC2 **หน้าเปลี่ยนรหัสผ่าน:** สไตล์เดียวกับหน้า login มีปุ่มแสดง/ซ่อนรหัส และลิงก์กลับหลังบ้าน
- [ ] AC3 **หน้าหลังบ้าน** (`/admin`):
  - แถบบนแสดงชื่อระบบ, username และปุ่ม "เปลี่ยนรหัสผ่าน" กับ "ออกจากระบบ" (บนมือถือย่อเหลือไอคอนหรือเมนูได้)
  - แถบสรุป "มีวีดีโอแล้ว X / 14 ชุด" พร้อม progress bar สีทอง
  - แบ่ง 2 หมวด "วีดีโอรายเดือน" (12 ชุด) และ "e-card" (2 ชุด)
  - การ์ดเรียงเป็น grid: 1 คอลัมน์บนมือถือ, 2 บนแท็บเล็ต, 3 บนจอใหญ่
  - แถบเตือน PUBLIC_ORIGIN (ถ้ามี) ยังแสดงเด่นชัดเหมือนเดิม
- [ ] AC4 **การ์ดแต่ละชุด:**
  - ป้ายหมายเลข (01–12 หรือ "e-card") และชื่อชุด
  - **ภาพ QR ขนาดเล็กบนการ์ด** (แสดง inline ได้ ไม่ต้องดาวน์โหลด) ใช้ URL เดียวกับ QR ที่ดาวน์โหลด
    - ถ้าชุดนั้น**มีวีดีโอแล้ว** ให้มีไอคอนเช็ก (วงกลมเขียว + ติ๊กถูก) ซ้อนที่มุม QR และป้ายสถานะ "✓ มีวีดีโอแล้ว" สีเขียว ขอบการ์ดเน้นขึ้น
    - ถ้า**ยังไม่มีวีดีโอ** ให้ป้ายสีเทา "ยังไม่มีวีดีโอ" และ QR ไม่มีเช็ก
    - ทำได้ด้วย route preview ใหม่ที่ต้องล็อกอิน เช่น `GET /admin/qr/:slug.svg?inline=1` (ไม่มี Content-Disposition attachment) หรือ render SVG ลงหน้าโดยตรง ต้องใช้กติกา PUBLIC_ORIGIN เดิมทุกอย่าง (production ไม่มี PUBLIC_ORIGIN → ไม่แสดง QR และมีแถบเตือน)
  - ขนาดไฟล์ และอัปเดตล่าสุดเมื่อไหร่ / โดยใคร
  - ปุ่มมีไอคอน: "ดูวีดีโอ" (แท็บใหม่), "คัดลอกลิงก์" (ขึ้น toast "คัดลอกลิงก์แล้ว"), "ดาวน์โหลด QR" (PNG / SVG), และปุ่มหลักสีทอง "อัปโหลดวีดีโอ" / "เปลี่ยนวีดีโอ"
  - แถบ progress ของการอัปโหลดเข้ากับธีม ปุ่มยกเลิกยังมี ข้อความสถานะเดิมยังครบ (รวม "กำลังบันทึก...")
  - อัปโหลดสำเร็จแล้วการ์ดเปลี่ยนเป็นสถานะ "มีวีดีโอแล้ว" พร้อมเช็กทันที (ไม่ต้อง reload) และตัวเลขในแถบสรุปเพิ่มขึ้น
- [ ] AC5 **ไม่เปลี่ยนพฤติกรรม:**
  - ไม่แตะ API, CSRF, session, กติกาอัปโหลด หรือข้อความแจ้งผล
  - หน้า `/v/<slug>` และ player ไม่เปลี่ยน
  - ไม่โหลดอะไรจากภายนอก
  - assets ใหม่ (css / js / fonts) อยู่ใน `public/assets/` และใช้ `?v=<hash>` แบบเดิม
- [ ] AC6 **Test:**
  - `npm test` ผ่านทั้งหมด และเพิ่ม test ของ AC1–AC4: มีเช็กเฉพาะชุดที่มีวีดีโอ, ตัวเลขสรุปถูกต้อง, preview QR ต้องล็อกอินและไม่เป็น attachment, ไม่มี URL ภายนอก, ฟอนต์เสิร์ฟได้
  - ถ้า test เดิม (รวม `test/qa-*.test.js`) ตรวจ markup เฉพาะที่เปลี่ยนไปโดยชอบธรรม ให้แก้ให้น้อยที่สุดโดยยังตรวจความหมายเดิม แล้วรายงานทุกจุดที่แก้ ห้ามลดสิ่งที่ตรวจ
- [ ] AC7 **ภาพหน้าจอ:** บันทึก screenshot หน้า login, หน้าหลังบ้าน (มีทั้งชุดที่มีและไม่มีวีดีโอ) และหน้าเปลี่ยนรหัส ทั้งขนาดมือถือ (390px) และคอมพิวเตอร์ (1280px) ลง scratchpad ของ Lead เพื่อให้ผู้ใช้ดูก่อน deploy (ถ้ามีเครื่องมือที่ใช้ได้ เช่น Chrome headless ใน WSL ถ้าไม่มีให้บอก Lead)
